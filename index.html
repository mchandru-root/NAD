How detection works

Port scan

Flags a source host that touches an unusual number of distinct destination ports in a short window — the classic signature of reconnaissance / nmap-style scanning.

Sensitive port access

Flags connections to high-risk services (RDP 3389, SMB 445, Telnet 23, FTP 21, MySQL 3306) — ports that are rarely meant to be internet-facing.

Volume anomaly

Computes a z-score on bytes-transferred per host against the capture's baseline. Large deviations can indicate data exfiltration or a misbehaving service.

Beaconing

Looks for a host calling out to the same destination at suspiciously regular intervals — a common command-and-control (C2) callback pattern.

Failed-connection ratio

Tracks the proportion of RST/incomplete handshakes from a source — elevated ratios suggest brute-forcing or scanning rather than normal traffic.

+ ML module

The companion Python script (/python) runs the same feature set through scikit-learn's IsolationForest for a second, unsupervised opinion — see the repo for the offline version.

About this project

NAD was built as a hands-on demonstration of SOC-style network anomaly detection: turning raw flow records into triaged, severity-ranked findings the way an analyst would in Wazuh, Splunk, or the Elastic stack. Everything on this page runs client-side in JavaScript — no server, no data leaves your browser — with a parallel Python/scikit-learn module in the repository for offline, ML-based analysis of the same data.

Stack: vanilla JS, HTML5 Canvas, CSV parsing — Python 3, pandas, scikit-learn (IsolationForest), matplotlib for the offline module.
